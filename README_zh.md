# 西雅图天气分类项目

**简体中文** | [English](README.md)

基于 Python 和 scikit-learn 的机器学习课程项目：利用降水量、最高温度、最低温度和风速，将天气分类为毛毛雨、雾、雨、雪或晴天。项目通过 Jupyter Notebook 实现数据读取、标签编码、数据划分、可视化、类别平衡、模型调参、测试评估及样本预测。

> 本文根据 `Assignment 3 weather classifer.ipynb` 的实际代码和已保存输出整理。结果来自原 Notebook，未重新训练验证。Notebook 开头的 Iris 数据集介绍及部分注释属于残留模板，与实际天气分类任务不符。

## 数据集

输入文件为 `seattle-weather.csv`。Notebook 展示的数据共 **1,461 条记录、6 个字段**，日期范围为 2012-01-01 至 2015-12-31。

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `date` | 日期 | 建模前删除 |
| `precipitation` | 降水量 | 输入特征 |
| `temp_max` | 最高温度 | 输入特征 |
| `temp_min` | 最低温度 | 输入特征 |
| `wind` | 风速 | 输入特征 |
| `weather` | 天气类别 | 预测目标 |

`LabelEncoder` 将目标编码为：`drizzle=0`、`fog=1`、`rain=2`、`snow=3`、`sun=4`。

原 Notebook 未提供可核实的天气数据来源及单位说明；运行前需自行准备 CSV。文档中的 Iris 数据链接不适用于本项目。

## 实现流程

1. 读取 CSV，编码天气标签，选取四个数值特征。
2. 使用 `random_state=42` 随机划分约 60% 训练集、20% 验证集、20% 测试集：分别为 876、292、293 条。
3. 从测试集保留两条记录用于模拟新样本预测，最终测试集为 291 条。
4. 绘制训练集四个特征的六种两两组合散点图。
5. 仅对训练集执行 SMOTE 过采样，以缓解类别不平衡。
6. 用户选择一个模型，遍历参数组合，以验证集准确率选择参数。
7. 合并过采样后的训练集与原始验证集，重新训练最终模型；逻辑回归、KNN 和 SVC 同时重新拟合标准化器。
8. 输出测试集准确率、宏平均精确率、召回率、F1、混淆矩阵和分类报告，并预测两条保留样本。

两条“未来样本”来自随机划分的测试集，只用于演示预测流程，不代表真实未来日期的预报。本项目根据同日气象观测判断天气类别，未实现时间序列预测。

## 可选模型

| 输入编号 | 模型 | 搜索的主要参数 | 标准化 |
| --- | --- | --- | --- |
| 1 | 决策树 | 划分准则、深度、最小分裂样本数、最小叶节点样本数 | 否 |
| 2 | 随机森林 | 树数量、划分准则、深度、分裂与叶节点限制、特征数量 | 否 |

每次运行选择一个模型，当前文件没有保存五种模型的完整对比结果，因此无法据此判断哪一种模型总体最优。

## 已保存实验结果

Notebook 保存的运行选择为 **KNN**，最佳验证参数为：

```python
{"n_neighbors": 1, "weights": "uniform", "p": 1}
```

其中 `p=1` 表示曼哈顿距离。

| 指标 | 结果 |
| --- | ---: |
| 验证集准确率 | 58.56% |
| 测试集准确率 | 62.89% |
| 测试集宏平均 Precision | 0.4177 |
| 测试集宏平均 Recall | 0.5113 |
| 测试集宏平均 F1 | 0.4360 |
| 两条演示样本准确率 | 100%（2/2） |

### 测试集分类报告

| 类别 | Precision | Recall | F1 | 样本数 |
| --- | ---: | ---: | ---: | ---: |
| drizzle | 0.08 | 0.17 | 0.11 | 12 |
| fog | 0.19 | 0.28 | 0.23 | 25 |
| rain | 0.85 | 0.81 | 0.83 | 129 |
| snow | 0.27 | 0.75 | 0.40 | 4 |
| sun | 0.70 | 0.55 | 0.62 | 121 |

模型对 rain 的识别效果较好，对 drizzle 和 fog 较弱。测试集中 rain 和 sun 占多数，整体准确率不能充分反映少数类别的表现。snow 只有 4 条测试样本，两条演示样本也不足以支持稳定的泛化结论。

## 运行方法

### 准备文件

将以下文件放在同一目录（此 README 不包含数据或 Notebook 副本）：

```text

├── README.md
```

### 本地 Jupyter

安装项目使用的依赖：

```bash
python -m pip install pandas numpy matplotlib scikit-learn imbalanced-learn jupyter
jupyter notebook
```

打开 Notebook 后：

1. 跳过或删除 `google.colab` 导入和 Google Drive 挂载单元格。
2. 跳过原有的 `cd /content/drive/...` 单元格，将工作目录设为 CSV 所在目录，或修改 `pd.read_csv()` 的路径。
3. 从头按顺序运行各单元格。
4. 在模型选择提示中输入 `1` 至 `5`。
5. 查看验证参数、测试指标、混淆矩阵及演示预测结果。

上述安装命令未锁定版本。原 Notebook 没有完整环境记录，逻辑回归分支使用的 `multi_class="auto"` 等接口可能与所装版本不兼容；若出现参数错误，需要适配当前安装版本。此处未对不同版本环境执行兼容性测试。

## 已知限制与后续改进

- **文档清理**：标题、Iris 介绍和部分训练/验证/测试图表注释与实际代码不一致；实际六张散点图均使用训练集。
- **评估设计**：当前采用单次随机划分，未使用分层抽样或交叉验证。可增加分层交叉验证，并以宏平均 F1 等指标辅助调参。
- **时间泛化**：若目标是预测未来天气，应重新设计预测目标、时间特征与按时间划分的评估方式。
- **预处理顺序**：当前先在原始量纲上执行 SMOTE，再为部分模型标准化。可使用流水线在训练折内完成标准化和采样，避免量纲影响近邻采样，并避免交叉验证中的数据泄漏。
- **结果比较**：应在统一评估协议下记录五种模型的结果，再作模型选择；当前不能声称 KNN 优于其他模型。
- **运行健壮性**：非法模型编号只打印提示，不会重新请求输入；非整数输入会报错。应加入输入校验。
- **数据质量与复现**：补充缺失值、重复值检查、数据来源、依赖版本和随机状态记录。
- **部署**：尚未实现模型持久化、预测接口或应用部署。部署时需共同保存模型、标准化器和标签编码器。
